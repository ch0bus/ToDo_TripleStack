# ToDo API Specification

Базовый REST API для работы с задачами (ToDo) с поддержкой пользователей
(аутентификация и авторизация). Все три бекэнда (Django, FastAPI, Flask) должны
реализовывать этот контракт.

## Базовые принципы

- Все ответы в формате JSON.
- Времена в формате ISO 8601 в UTC, например: `"2026-09-04T12:00:00Z"`.
- Язык ошибок: любой, но структура должна быть одинаковой.
- Все операции с задачами выполняются **от имени аутентифицированного пользователя**.
- Каждая задача принадлежит конкретному пользователю; пользователь видит и изменяет
  только свои задачи.

## Модель User

Минимальная логическая модель пользователя (как она будет реализована в конкретном
фреймворке — не принципиально, важен контракт API).

```json
{
  "id": 1,
  "username": "user1"
}
```

### Поля
- `id` (integer, read-only) — уникальный идентификатор пользователя.
- `username` (string, required, 3..150) — логин (уникальный).

Пароль **никогда** не возвращается в ответах API.

## Модель Todo

```json
{
  "id": 1,
  "user_id": 1,
  "title": "Купить молоко",
  "description": "2 литра",
  "completed": false,
  "created_at": "2026-09-04T12:00:00Z",
  "updated_at": "2026-09-04T12:30:00Z"
}
```

### Поля
- `id` (integer, read-only) — уникальный идентификатор задачи.
- `user_id` (integer, read-only) — ID владельца задачи (авторизованный пользователь).
- `title` (string, required, 1..255) — краткий заголовок задачи.
- `description` (string, optional, 0..2000) — подробное описание.
- `completed` (boolean, default: false) — статус выполнения.
- `created_at` (string, read-only) — дата и время создания.
- `updated_at` (string, read-only) — дата и время последнего обновления.

## Общий формат ответа об ошибке

Во всех бекэндах ошибки должны возвращаться в едином формате:

```json
{
  "detail": "Сообщение об ошибке",
  "errors": {
    "field_name": ["Описание ошибки поля"]
  }
}
```

- `detail` — общая информация об ошибке (может быть строкой или объектом).
- `errors` — объект с ошибками по полям (может отсутствовать, если не применимо).

## Аутентификация и авторизация

Используется **JWT через заголовок Authorization**.

- Клиент передаёт токен в заголовке:

  ```http
  Authorization: Bearer <token>
  ```

- Все эндпоинты, работающие с задачами (`/api/todos/...`) требуют аутентификации.
- Без валидного токена сервер отвечает `401 Unauthorized`.
- При попытке доступа к чужим ресурсам сервер отвечает `403 Forbidden`.

(Внутренняя реализация JWT в каждом бекэнде может отличаться, важно только поведение.)

## Эндпоинты аутентификации

Базовый URL для API: `/api`.

### 0. Регистрация пользователя

**POST** `/api/auth/register`

Тело запроса:

```json
{
  "username": "user1",
  "password": "string_min_8_chars"
}
```

Требования:
- `username` — уникальный, 3..150 символов.
- `password` — минимум 8 символов.

#### Успешный ответ

- Статус: `201 Created`
- Тело:

```json
{
  "id": 1,
  "username": "user1"
}
```

#### Ошибки

- `400 Bad Request` — невалидные данные.
- `409 Conflict` — пользователь с таким `username` уже существует (можно
  также возвращать `400`, но важно единообразие между бэкендами).

Пример ошибки:

```json
{
  "detail": "Validation error",
  "errors": {
    "username": ["Username already taken"]
  }
}
```

### 0.1. Логин (получение токена)

**POST** `/api/auth/login`

Тело запроса:

```json
{
  "username": "user1",
  "password": "string_min_8_chars"
}
```

#### Успешный ответ

- Статус: `200 OK`
- Тело:

```json
{
  "access_token": "jwt_token_string",
  "token_type": "bearer"
}
```

#### Ошибки

- `400 Bad Request` — невалидные данные (например, пустой логин/пароль).
- `401 Unauthorized` — неверные логин или пароль.

```json
{
  "detail": "Invalid username or password"
}
```

### 0.2. Текущий пользователь (опционально)

**GET** `/api/auth/me`

Требуется заголовок `Authorization: Bearer <token>`.

#### Успешный ответ

- Статус: `200 OK`
- Тело:

```json
{
  "id": 1,
  "username": "user1"
}
```

#### Ошибки

- `401 Unauthorized` — если токен отсутствует или недействителен.

```json
{
  "detail": "Not authenticated"
}
```

## Эндпоинты работы с задачами

> Все запросы ниже требуют заголовка `Authorization: Bearer <token>`.
> 
> Во всех ответах возвращаются только задачи текущего аутентифицированного
> пользователя.

### 1. Получить список задач

**GET** `/api/todos`

Параметры запроса (query):
- `completed` (optional, boolean) — фильтр по статусу (true/false).
- `search` (optional, string) — поиск по заголовку/описанию.

#### Успешный ответ

- Статус: `200 OK`
- Тело:

```json
[
  {
    "id": 1,
    "user_id": 1,
    "title": "Купить молоко",
    "description": "2 литра",
    "completed": false,
    "created_at": "2026-09-04T12:00:00Z",
    "updated_at": "2026-09-04T12:00:00Z"
  }
]
```

#### Ошибки

- `401 Unauthorized` — если нет или неверный токен.

### 2. Создать задачу

**POST** `/api/todos`

Тело запроса:

```json
{
  "title": "Купить молоко",
  "description": "2 литра",
  "completed": false
}
```

`user_id` задаётся автоматически на основе текущего пользователя.

Разрешённые поля:
- `title` (required)
- `description` (optional)
- `completed` (optional, default: false)

#### Успешный ответ

- Статус: `201 Created`
- Тело: созданный объект Todo.

```json
{
  "id": 1,
  "user_id": 1,
  "title": "Купить молоко",
  "description": "2 литра",
  "completed": false,
  "created_at": "2026-09-04T12:00:00Z",
  "updated_at": "2026-09-04T12:00:00Z"
}
```

#### Ошибки

- `400 Bad Request` — невалидные данные.
- `401 Unauthorized` — нет токена или он недействителен.

### 3. Получить задачу по ID

**GET** `/api/todos/{id}`

#### Успешный ответ

- Статус: `200 OK`
- Тело: объект Todo.

#### Ошибки

- `401 Unauthorized` — нет/невалидный токен.
- `404 Not Found` — задача не найдена **среди задач текущего пользователя**.

```json
{
  "detail": "Todo not found"
}
```

> Если задача существует у другого пользователя, API всё равно должен
> отвечать `404 Not Found`, не раскрывая сам факт существования ресурса.

### 4. Полное обновление задачи

**PUT** `/api/todos/{id}`

Тело запроса (все поля, кроме read-only и `user_id`):

```json
{
  "title": "Купить хлеб",
  "description": "Чёрный",
  "completed": true
}
```

#### Успешный ответ

- Статус: `200 OK`
- Тело: обновлённый объект Todo.

#### Ошибки

- `400 Bad Request` — невалидные данные.
- `401 Unauthorized` — нет/невалидный токен.
- `404 Not Found` — задача не найдена у текущего пользователя.

### 5. Частичное обновление задачи

**PATCH** `/api/todos/{id}`

Тело запроса (любое подмножество полей, кроме `user_id`):

```json
{
  "completed": true
}
```

#### Успешный ответ

- Статус: `200 OK`
- Тело: обновлённый объект Todo.

#### Ошибки

- `400 Bad Request` — невалидные данные.
- `401 Unauthorized` — нет/невалидный токен.
- `404 Not Found` — задача не найдена у текущего пользователя.

### 6. Удалить задачу

**DELETE** `/api/todos/{id}`

#### Успешный ответ

- Статус: `204 No Content`
- Тело: пусто.

#### Ошибки

- `401 Unauthorized` — нет/невалидный токен.
- `404 Not Found` — задача не найдена у текущего пользователя.

### 7. Переключить статус задачи

**POST** `/api/todos/{id}/toggle`

Меняет поле `completed` на противоположное.

#### Успешный ответ

- Статус: `200 OK`
- Тело: обновлённый объект Todo.

```json
{
  "id": 1,
  "user_id": 1,
  "title": "Купить молоко",
  "description": "2 литра",
  "completed": true,
  "created_at": "2026-09-04T12:00:00Z",
  "updated_at": "2026-09-04T12:30:00Z"
}
```

#### Ошибки

- `401 Unauthorized` — нет/невалидный токен.
- `404 Not Found` — задача не найдена у текущего пользователя.

## Статусы ответов (сводка)

- `200 OK` — успешный запрос (получение, обновление, toggle, login, me).
- `201 Created` — успешно создан ресурс (пользователь, задача).
- `204 No Content` — успешно удалён ресурс.
- `400 Bad Request` — ошибка валидации входных данных.
- `401 Unauthorized` — требуется аутентификация или токен недействителен.
- `403 Forbidden` — действие запрещено (если явно понадобится отличать от 404).
- `404 Not Found` — ресурс не найден.
- `409 Conflict` — конфликт данных (например, дублирующий username).

Эта спецификация — базовый контракт, от которого должны отталкиваться все три сервера
(Django, FastAPI, Flask) и frontend.

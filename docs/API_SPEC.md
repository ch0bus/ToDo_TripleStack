# Haloday API Specification

REST API личного планера (задачи, события, заметки дня, смены) с JWT-аутентификацией.
Контракт общий для Django, FastAPI и Flask; текущая эталонная реализация — **Django** (`backend/django_api`).

Базовый URL: `/api` (у Django пути со слэшем в конце). Интерактивная документация: `/api/docs/`.

## Принципы

- Ответы в JSON, даты в ISO 8601 UTC (`2026-09-04T12:00:00Z`).
- Данные **персональные**: todos, события, личные теги, подзадачи, смены и заметки дней фильтруются по пользователю из JWT.
- Общего календаря и общих списков нет. Календарь в UI — представление своих задач, событий и смен.
- Чужие ресурсы → `404 Not Found` (не `403`), где применимо.
- Заголовок: `Authorization: Bearer <access_token>`.

## Ошибки

```json
{
  "detail": "Сообщение об ошибке",
  "field_name": ["Ошибка поля"]
}
```

Формат может отличаться (`errors` vs плоские поля); клиент должен показывать `detail` или первое поле.

## Auth

### POST `/api/auth/register/`

Тело: `{ "username", "email", "password" }` (пароль ≥ 8 символов).

- `201` — `{ "id", "username", "email" }`
- `400` — валидация

### POST `/api/auth/login/`

Тело: `{ "username", "password" }`.

- `200` — `{ "access", "refresh" }` (JWT SimpleJWT)
- `401` — неверные учётные данные

### POST `/api/auth/token/refresh/`

Тело: `{ "refresh": "<refresh_token>" }`.

- `200` — `{ "access" }` (и опционально новый `refresh`, если включена ротация)
- `401` — refresh недействителен

### GET `/api/auth/me/`

- `200` — `{ "id", "username", "email", "phone_number" }`
- `401`

### PATCH `/api/auth/me/`

Тело (любое подмножество): `{ "email", "phone_number", "password" }` (пароль ≥ 8).

- `200` — обновлённый профиль
- `400` — валидация

PIN и биометрия в UI — только локальный замок браузера (не API). JWT по-прежнему выдаётся логином и паролем. Забытый PIN сбрасывает замок и требует пароль.

## Telegram

Каждый пользователь указывает **своего** бота (токен BotFather) в настройках.
Чужие задачи не отдаются. Инструкция: [`TELEGRAM.md`](TELEGRAM.md).

### GET `/api/telegram/`

- `200` — `{ "configured", "connected", "bot_username", "token_hint", "chat_username", "timezone", "digest_hour", "remind_minutes", "deep_link", "timezones" }`
- `token` в ответе нет, только `token_hint` (последние 4 символа)
- `401`

### PUT `/api/telegram/`

Тело (все поля опциональны, кроме первого сохранения): `{ "token", "timezone", "digest_hour", "remind_minutes" }`.

Пустой `token` оставляет прежний. Новый токен проверяется через Telegram `getMe`. Смена токена сбрасывает привязку чата.

- `200` — тот же объект, что GET
- `400` — токен неверный, занят другим аккаунтом, или нет токена при первом сохранении
- `401`

### DELETE `/api/telegram/`

Удалить бота. `204`.

### POST `/api/telegram/unlink/`

Отвязать чат, токен оставить. `200` — статус как GET.

Первый `/start` в личке бота привязывает чат. Текст создаёт задачу (`event_date` = сегодня 09:00 в поясе бота). Кнопка `d:<todo_id>` отмечает **свою** задачу.

## Todo

### Модель (ответ)

```json
{
  "id": 1,
  "user_id": 1,
  "title": "Купить молоко",
  "description": "2 литра",
  "status": "todo",
  "priority": "medium",
  "event_date": "2026-09-06T15:00:00Z",
  "due_date": "2026-09-04T18:00:00Z",
  "recurrence": "never",
  "tags": [
    { "id": 1, "tag_name": "покупки", "kind": "shopping" }
  ],
  "created_at": "2026-09-04T12:00:00Z",
  "updated_at": "2026-09-04T12:30:00Z",
  "completed_at": null
}
```

**status:** `todo` | `in_progress` | `done`  
**priority:** `critical` | `high` | `medium` | `low` (по умолчанию `low`)  
**recurrence:** `daily` | `weekly` | `monthly` | `never`  
**event_date:** когда происходит событие (календарь, повтор).  
**due_date:** дедлайн выполнения (просрочка, «Сегодня» по сроку).  
**created_at:** read-only, момент создания карточки.  
**completed_at:** read-only. Ставится при переходе в `done`, сбрасывается при любом другом статусе.

При **создании/обновлении** теги передаются полем **`tag_ids`**: `[1, 2]` (write-only).

### GET `/api/todos/`

Query (все опционально):

| Параметр   | Описание                          |
|-----------|-----------------------------------|
| `status`  | Фильтр по статусу                 |
| `priority`| Фильтр по приоритету              |
| `tag`     | ID тега                           |
| `due_from`| Срок ≥ (ISO datetime)             |
| `due_to`  | Срок ≤ (ISO datetime)             |
| `from`    | Вместе с `to`: окно календаря `YYYY-MM-DD` (якорь `event_date` или `due_date`, повторы `created_at`…якорь, плюс задачи без даты). Не больше 366 дней. |
| `to`      | Конец окна календаря              |
| `search`  | Поиск в title/description         |
| `overdue` | `true` — просроченные (не `done`) |
| `due_today` | `true` — срок сегодня (TZ сервера) |

- `200` — массив Todo, сортировка `-created_at` (новые сверху)

Каждый элемент может содержать **`subtasks_summary`**: `{ "done": 2, "total": 3 }`.

### GET `/api/todos/stats/`

- `200`:

```json
{
  "total": 12,
  "done": 5,
  "in_progress": 4,
  "overdue": 2
}
```

### POST `/api/todos/`

Тело (минимум `title`):

```json
{
  "title": "Задача",
  "description": "",
  "status": "todo",
  "priority": "low",
  "event_date": null,
  "due_date": null,
  "recurrence": "never",
  "tag_ids": [1]
}
```

- `201` — созданный Todo (с вложенными `tags`)

### GET / PUT / PATCH / DELETE `/api/todos/{id}/`

Стандартный CRUD; `user_id` только read-only.

**Повторение** — правило на задаче, не отдельные строки в БД:

- окно: от дня `created_at` до дня `event_date`, а если события нет — до `due_date`;
- шаг `daily` / `weekly` / `monthly`;
- на календаре задача стоит в день события (или срока, если события нет);
- без события и без срока повторы не рисуются;
- при переходе в `done` новая копия задачи **не** создаётся.

## Tags

### POST `/api/tags/`

Тело: `{ "tag_name", "kind" }` — создаёт **личный** тег.

### DELETE `/api/tags/{id}/`

Удаление личного тега (реализация может ограничивать системные).

## Смены (календарь)

Типы смен, шаблон и правки дней — **свои у каждого пользователя**.
До 10 **календарей смен** (доска «Основной» создаётся сама). Задачи и заметки дня общие, не зависят от выбранной доски.
У каждого календаря два именованных слоя (по умолчанию «Слой 1» и «Слой 2»). У слоя свои типы, цикл и ручные дни.
Тип: имя, цвет `#RRGGBB`, продолжительность (часы), перерыв (минуты), ставка ₽/час.
Цикл слоя разворачивается с `start_date` до `end_date` (пусто — без конца).
Ручная метка дня перекрывает шаблон слоя и действует и вне окна цикла.

Эндпоинты слоёв, типов, шаблона и дней принимают `?calendar={id}`. Без параметра — первый календарь пользователя.

### GET / POST `/api/shift-calendars/`

- `GET` — доски смен (создаёт «Основной», если ещё нет)
- `POST` — `{ "name": "Подработка" }` (не больше 10)

### PATCH / DELETE `/api/shift-calendars/{id}/`

Последнюю доску удалить нельзя.

### GET / PATCH `/api/shift-layers/`

- `GET ?calendar={id}` — два слоя выбранной доски
- `PATCH /api/shift-layers/{id}/` — `{ "name": "Слой 2" }`

### GET / POST `/api/shift-kinds/`

- `GET` — типы смен; `?layer={id}` — только слой
- `POST` — `{ "layer_id": 1, "name": "Ночь", "color": "#7c3aed", "duration_hours": "11.00", "break_minutes": 60, "hourly_rate": "250.00" }`

### PATCH / DELETE `/api/shift-kinds/{id}/`

### GET / PUT `/api/shift-pattern/`

`GET` без `layer` — список шаблонов обоих слоёв. `GET ?layer={id}` — один шаблон.

```json
{
  "layer_id": 1,
  "start_date": "2026-09-01",
  "end_date": "2026-12-31",
  "slots": [
    { "kind_id": 1 },
    { "kind_id": 1 },
    { "kind_id": null },
    { "kind_id": null }
  ]
}
```

`end_date: null` — цикл без конца. `kind_id: null` — выходной в цикле. Пустой `slots` — только ручные метки. Типы в слотах должны принадлежать этому слою.

### GET `/api/shift-days/?from=YYYY-MM-DD&to=YYYY-MM-DD`

Развёрнутые дни обоих слоёв выбранной доски (`pattern` или `override`). `?calendar={id}`. Элемент: `{ date, layer_id, kind, source }`. Диапазон не больше 366 дней.

### PUT `/api/shift-days/`

`{ "date": "2026-09-15", "layer_id": 1, "kind_id": 1 }` — ручная метка слоя. `kind_id: null` — выходной.

### DELETE `/api/shift-days/{date}/?layer={id}`

Убрать ручную метку слоя, вернуть день к шаблону этого слоя.

## Заметки дня

Одна заметка на календарный день у пользователя. На месяце — золотая полоска в столбике дня; на году входит в общую точку занятости. Во входящих карточка заметки с золотой рамкой. Сегодня — нимб у числа (месяц и год).

### GET `/api/day-notes/?from=YYYY-MM-DD&to=YYYY-MM-DD`

Список своих заметок в диапазоне (не больше 366 дней).

```json
[{ "date": "2026-09-12", "text": "Смена графика", "updated_at": "2026-09-12T12:00:00Z" }]
```

### PUT `/api/day-notes/`

`{ "date": "2026-09-12", "text": "Смена графика" }` — создать или заменить.

### GET `/api/day-notes/{date}/`

Своя заметка на день. `404`, если её нет.

### DELETE `/api/day-notes/{date}/`

Удалить заметку дня.

## Events

Именованный факт во времени (встреча, день рождения, отпуск). Не задача: без статуса, приоритета, срока и подзадач. Во входящих показывается в блоке выбранного дня.

```json
{
  "id": 1,
  "title": "Стоматолог",
  "description": "",
  "start_at": "2026-09-18T10:00:00Z",
  "end_at": "2026-09-18T11:00:00Z",
  "all_day": false,
  "recurrence": "never",
  "color": "#e11d48",
  "created_at": "2026-09-14T12:00:00Z",
  "updated_at": "2026-09-14T12:00:00Z"
}
```

**recurrence:** как у задач (`daily` | `weekly` | `monthly` | `never`), повтор от `start_at` вперёд.  
**end_at:** опционально, не раньше `start_at`. Если конец в другой день — событие занимает все дни диапазона.  
**all_day:** без времени в UI.  
**color:** `#RRGGBB`, цвет полоски события на месяце, по умолчанию `#e11d48`.

### GET `/api/events/`

Query (опционально, только вместе): `from`, `to` — окно `YYYY-MM-DD`, не больше 366 дней. Разовое событие попадает, если `start_at`…`end_at` пересекает окно; повтор — если `start_at` не позже `to` (серия идёт вперёд). Без параметров — все события пользователя.

- `200` — массив Event, сортировка `start_at`

### POST `/api/events/`

Тело (минимум `title` и `start_at`):

```json
{
  "title": "Стоматолог",
  "description": "",
  "start_at": "2026-09-18T10:00:00Z",
  "end_at": null,
  "all_day": false,
  "recurrence": "never",
  "color": "#e11d48"
}
```

- `201` — созданное Event

### GET / PUT / PATCH / DELETE `/api/events/{id}/`

Стандартный CRUD; только свои события (`404` чужие).

## Frontend (Vite)

- Dev: `http://localhost:5173`, proxy `/api` → Django `:8000`.
- Переменная: `VITE_API_URL` (пусто = `/api` через proxy).
- Бренд в UI: **Haloday** (словомарк с золотым нимбом на месте буквы o).

Маршруты UI: `/`, `/todos/new`, `/todos/:id`, `/notes/:date`, `/events/new`, `/events/:id`, `/calendar`, `/settings`, `/settings/shifts`, `/login`, `/register`.
В **Настройках → Telegram** пользователь указывает своего бота (токен BotFather, пояс, час сводки). Токен в JSON не возвращается. Подробности: [`TELEGRAM.md`](TELEGRAM.md).
Быстрый вход (PIN, WebAuthn) хранится в `localStorage` клиента и не ходит на сервер. Выборочное скрытие системных тегов — тоже локальная настройка устройства.
Создание задачи, события и заметки в UI — селектор «+ Добавить» на входящих и в календаре.
Сортировка списков — query `sort` (`new`, `created`, `due`, `priority`): на входящих только «Все задачи» (по умолчанию новые сверху), в календаре списки «Задачи дня / недели / месяца / года» (по умолчанию по сроку). API всегда отдаёт `-created_at`.
События периода на `/calendar`: списки «События дня / недели / месяца / года», query `esort` (`start`, `new`, `title`) и `ecolor` (цвет). Сетка и выбранный день от этих параметров не зависят. На входящих события в блоке выбранного дня (`?day=YYYY-MM-DD`, без параметра — сегодня). Просрочено / Все / Готово от выбранного дня не зависят.

Календарь (`/calendar`) грузит `/todos/?from=&to=`, `/events/?from=&to=`, `/shift-days/` и `/day-notes/` на видимый день, неделю, месяц (сетка 42 дня) или год (`?view=day|week|month|year`, без `view` — месяц). Без `from`/`to` API по-прежнему отдаёт весь список (входящие).
Доска смен выбирается `?calendar=id`. Сводка смен выбранного дня — блок с меню: настройки на `/settings/shifts`, рисование (кисть под сеткой месяца). Задачи ставятся в день `event_date`, иначе `due_date`. События — по `start_at`…`end_at`. На дне и неделе: с часами — на сетке (событие цветом, задача акцентом), полночь и «весь день» — в строке сверху; список задач выбранного дня остаётся под сеткой. Ниже — уникальные списки задач и событий выбранного периода (день, неделя, месяц или год). Смены двух слоёв заливают день по диагонали.
День на месяце — столбик полосок (событие цветом, задача акцентом, заметка золотом; на десктопе с заголовком). На году — одна точка занятости. Сегодня — нимб у числа.

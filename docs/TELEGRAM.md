# Telegram в Haloday

У каждого аккаунта **свой** бот. Пользователь создаёт его в BotFather и вписывает
токен в **Настройки → Telegram**. Общего бота на сервере нет, `TELEGRAM_BOT_TOKEN`
в `.env` не используется.

В чат попадают только задачи, события и заметки этого аккаунта. Группы бот игнорирует.
Первый `/start` в личке привязывает чат; сообщение от другого человека в том же
боте не создаёт чужие задачи.

Контракт API: [`API_SPEC.md`](API_SPEC.md) (раздел Telegram). Таблица: [`DB_SCHEMA.md`](DB_SCHEMA.md) (`telegram_bots`).

## 1. Пользователь: создать бота

1. Откройте [@BotFather](https://t.me/BotFather).
2. `/newbot` — отображаемое имя (например `Мой Haloday`) и username (`my_haloday_bot`).
3. Скопируйте токен вида `123456:AAH…`. Его нельзя слать другим и нельзя класть
   в git или `VITE_*`.
4. По желанию `/setdescription` — что это личный планер.

Один токен — один аккаунт Haloday. Если токен уже сохранён у другого пользователя,
сервер ответит ошибкой.

## 2. Пользователь: настройки в приложении

**Настройки → Telegram:**

| Поле | Что делает |
|------|------------|
| Токен бота | Обязателен при первом сохранении. Проверяется через Telegram `getMe`. |
| Часовой пояс | «Сегодня», сводка и время в сообщениях. |
| Сводка, час | Локальный час утреннего дайджеста (0–23). |
| Напоминание, мин | За сколько минут писать о `due_date` и о начале события со временем. «Весь день» — в час сводки. |

Дальше **Сохранить бота** → открыть ссылку на бота → в Telegram нажать **Start**.

После сохранения токен в форму не возвращается, виден только хвост (`…abcd`).
Пустое поле токена при следующем сохранении оставляет прежний ключ. Смена токена
сбрасывает привязку чата — Start нужно нажать снова.

- **Отвязать чат** — бот и параметры остаются, `/start` можно повторить.
- **Удалить бота** — токен стирается с аккаунта.

Пояса в списке: Калининград, Москва, Самара, Астрахань, Екатеринбург, Омск,
Новосибирск, Красноярск, Иркутск, Якутск, Владивосток, Магадан, Камчатка, UTC.

## 3. Что умеет бот

После привязки личного чата внизу экрана меню:

- **Новая задача** — название, затем дата на календаре: Сегодня, Завтра или сетка месяца. Время — 09:00 в поясе бота. Это **задача** (`event_date`), не встреча.
- **Новое событие** — название, затем та же дата. Создаётся **встреча** (`Event`) на весь день (`all_day`, `start_at` = полночь выбранного дня). Не задача.
- **Новая заметка** — текст, затем дата. Одна заметка на день (`DayNote`); если на эту дату уже есть текст, новый дописывается в конец.
- **Сегодня** / **Завтра** / **Просрочено** — списки; у задач кнопка **Готово**, у событий **Был** (посещение вхождения, не статус задачи). В сводке дня есть и заметка, если она сохранена. «Просрочено» включает пропущенные события (для повтора — последнее вхождение без отметки). Пока визард открыт, эти кнопки сбрасывают черновик и показывают список.
- любой другой текст (не команда) → задача на сегодня (`event_date` = сегодня 09:00 в поясе бота);
- `/today` — как «Сегодня»;
- `/stop` — отвязать чат (как «Отвязать чат» в настройках);
- `/help` — краткая справка;
- **Готово** — только **своя** задача: после создания, в сводке дня и в напоминании о сроке;
- **Был** — своё событие, одно вхождение (`e:<id>:<YYYY-MM-DD>`); повторно «Уже отмечено». Не кнопка «Готово»;
- утром в выбранный час — сводка дня с **Готово** у задач и **Был** у событий;
- за N минут до срока задачи и до начала события со временем; событие на весь день — отдельным сообщением в час сводки («Сегодня …, весь день», кнопка **Был**).

Повторы как на календаре (виртуальные вхождения) в бот не раскрываются: в чат
идут сохранённые даты.

## 4. Сервер (разработчик / VPS)

Нужен процесс, который опрашивает **все сохранённые токены** (`getUpdates`) и
шлёт напоминания. Без него Start и дайджест не работают.

После обновления кода:

```bash
python manage.py migrate
```

Локально — второй терминал рядом с `runserver`:

```bash
cd backend/django_api
python manage.py telegram_worker --loop
```

Только дайджест и напоминания, без опроса чатов:

```bash
python manage.py telegram_tick
```

Docker: сервис `telegram` в `docker-compose.yml`, тот же том SQLite, что у API.
Токен в `.env` **не задают**. После выкладки:

```bash
docker compose up -d --build
docker compose logs -f telegram
```

Пока никто не сохранил бота, воркер просто ждёт. HTTPS-webhook не используется:
на текущем деплое сайт на HTTP, Telegram webhook без TLS не принимают. Не
включайте `setWebhook` на пользовательских ботах — иначе `getUpdates` у воркера
перестанет получать сообщения.

Значения **новой** формы, пока пользователь ничего не сохранил (не токены ботов):

```env
TELEGRAM_TZ=Europe/Moscow
TELEGRAM_DIGEST_HOUR=8
TELEGRAM_REMIND_MINUTES=30
```

## 5. Если не работает

| Симптом | Что проверить |
|---------|----------------|
| «Telegram не принял токен» | Токен из BotFather целиком, без пробелов и слова `bot`. |
| «Этот бот уже добавлен в другом аккаунте» | Нужен другой бот / другой токен. |
| Start без реакции | Запущен ли `telegram_worker` или контейнер `telegram`; после смены токена — новый Start. |
| Нет сводки и напоминаний | Пояс и час в настройках, чат привязан (в блоке Telegram статус «Вкл»). |
| Задачи нет на сайте | Тот же аккаунт Haloday, куда вставили этот токен. |
| Чужие задачи в чате | Так быть не должно: бот ходит только в свой `chat_id` и только к своему `user_id`. |

Эндпоинты (JWT, кроме того что описано в спеке): `GET/PUT/DELETE /api/telegram/`,
`POST /api/telegram/unlink/`. Поле `token` в ответах отсутствует.
